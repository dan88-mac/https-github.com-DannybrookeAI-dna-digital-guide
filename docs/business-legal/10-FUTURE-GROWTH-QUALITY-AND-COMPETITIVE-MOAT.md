# Future growth, quality control & competitive moat

## Principle: no dead-end product

Every release must map to **Phase 1–5** in doc 08 and a **measurable KPI** in doc 07.

## Quality control program

| Layer | Control |
|-------|---------|
| Product | Acceptance criteria per module in blueprint |
| Code | Strict TS, Zod boundaries, CI required |
| Security | RLS, CSP, webhook idempotency, secret rotation |
| Support | Playbooks for failed heals + credit refunds policy |
| Community | Template review before “featured” badge |

## Competitive differentiation (maintain lead)

1. **Self-healing in-path** — not a separate observability bolt-on  
2. **Exportable Next.js** — developers own runtime artifacts  
3. **Purpose-driven community** — templates + stories, not anonymous zaps  
4. **Offline-first builder** — return visits without friction  
5. **Transparent economics** — credits aligned to value (heal success)  

## Competitor response matrix

| Threat | Response |
|--------|----------|
| iPaaS adds “AI fix” | Deeper heal policies + audit + codegen |
| Low-code price war | Community tier + template network effects |
| Open-source clone | Enterprise compliance + hosted runtime SLA |
| API cost spike | Model routing, caching, tiered heal depth |
